CKH Connect · n8n migration · rebuilt 2026-09-24

The n8n design, rebuilt on n8n-native primitives

The original 20-workflow build (ported from agent.mjs's shape) has been archived. This is the ground-up rebuild: 5 pipeline workflows and 10 shared sub-workflows, derived from n8n's own primitives rather than mirroring five poll loops. Click any node for its breakdown.

What changed and why: raw Postgres is gone — every plain read/write uses the native Supabase node (its own supabaseApi credential), with a generic HTTP call to /rest/v1/rpc/* reserved for the handful of genuinely stored-procedure-shaped operations (finalize_contact_match and the locking claim RPCs). Polling is gone — every pipeline is triggered by a Supabase Database Webhook, with a slow Schedule Trigger kept only as a missed-webhook backstop. The Postgres circuit_breaker table is gone — that's n8n's own state now, held in a native Data Table. Every skill runs on the AI Agent node uniformly, with a Structured Output Parser subnode doing schema validation natively — no more hand-rolled Zod-in-a-Code-node.
